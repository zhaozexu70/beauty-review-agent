# Prompt 迭代记录（v1 → v2）

> 本文所有数字都来自实际运行并保存在 `outputs/eval_results/` 的结果文件，可用 `scripts/evaluate.py` 复现。
> 模型：`deepseek-chat`，temperature=0，每批 20 条评论，JSON 输出 + pydantic 校验，不合格的条目重问一次。

## 1. 评测设计

| 项目 | 说明 |
|---|---|
| 评测集 | `data/eval/eval_set.csv`：从清洗后的 9,984 条洗发水评论中抽 300 条，正/负各 150，`random_state=42` |
| Holdout 集 | `data/eval/holdout_set.csv`：另外 300 条（正/负各 150），与评测集**不重叠**，写 prompt 时**从未打开看过**，只用于检查改进是否泛化 |
| 金标准 | 数据集自带的二分类标签（1=正向，0=负向） |
| 中性怎么算 | 模型可以输出 neutral，但金标准只有正/负，所以**预测为中性一律算错**，并单独报告“中性率” |
| Macro-F1 | 只在 positive / negative 两个金标准类别上取平均；中性和失败的预测会拉低对应类别的召回率 |
| JSON 失败率 | 重问一次后仍然不合格（JSON 无效、标签不在固定体系内、超过 2 个标签、漏掉 id）的条目占比 |
| 稳定性 | 关掉缓存，用同一个 prompt 跑两遍，统计“情感和标签集合都完全相同”的评论占比 |
| 标签准确率 | **没有报告**：标签没有人工金标准。已准备 50 条待人工标注的表（`data/eval/tag_labeling_sheet.csv`），标完后运行 `scripts/tag_agreement.py` 计算一致率 |

## 2. 结果对比

### 评测集（300 条）

| 指标 | v1 | v2 | 变化 |
|---|---:|---:|---:|
| 准确率（中性算错） | 90.33% | **98.00%** | +7.67 个百分点 |
| Macro-F1（正/负） | 0.9466 | **0.9832** | +0.0366 |
| 中性率 | 9.33% | 0.67% | −8.67 个百分点 |
| 非中性样本上的准确率 | 99.63%（272 条） | 98.66%（298 条） | −0.97 个百分点 |
| JSON 失败率（重问后） | 0.00% | 0.00% | — |
| 触发重问的批次 / 条目 | 2 批 / 6 条 | 2 批 / 3 条 | — |
| 稳定性：情感+标签都相同 | 95.67% | 94.67% | −1.00 个百分点 |
| 稳定性：仅情感相同 | 100.00% | 99.67% | |
| 稳定性：仅标签相同 | 95.67% | 95.00% | |
| 单次评测估算花费 | ¥0.0551 | ¥0.0776 | v2 prompt 更长、多了 reason 字段 |

### Holdout 集（300 条，写 prompt 时没看过）

| 指标 | v1 | v2 | 变化 |
|---|---:|---:|---:|
| 准确率（中性算错） | 90.00% | **95.67%** | +5.67 个百分点 |
| Macro-F1（正/负） | 0.9414 | **0.9663** | +0.0249 |
| 中性率 | 9.00% | 2.00% | −7.00 个百分点 |
| 非中性样本上的准确率 | 98.90% | 97.62% | −1.28 个百分点 |
| JSON 失败率 | 0.00% | 0.00% | — |

**怎么解读：**
1. v1 的错误几乎全是“预测为中性”（29 个错误里 28 个），v1 只要给出正/负判断，准确率就有 99.63%。所以 v1 的主要问题不是“看不懂情感”，而是**“中性”的定义和数据标签的定义不一致**。
2. v2 把中性率从 9.33% 降到 0.67%，但代价是：原来判为中性的评论，被迫选了正/负，其中少数选错了，于是“非中性样本准确率”略降。
3. v2 是对着评测集的 badcase 写的，所以评测集上的提升（+7.67）**偏乐观**；holdout 上的提升（+5.67）才是更可信的数字。这个差距说明 v2 对评测集有一定“过拟合”。
4. 稳定性 v2 没有变好（94.67% vs 95.67%）。不一致主要来自标签：模型在“要不要加第二个标签”上摇摆（例如 `包装` vs `包装|物流`）。temperature=0 也不能保证完全一致，这正是要单独测稳定性的原因。

## 3. v1 badcase 分析 → v2 改了什么

v1 在评测集上有 29 个错误（文件：`outputs/eval_results/v1/badcases.csv`）。我逐条读完后人工归成 4 类，每条的归类保存在 `outputs/eval_results/v1/badcase_categories.csv`：

| 错误类型 | 数量 | 其中 v2 修好 | 例子 |
|---|---:|---:|---|
| A. 未使用/只陈述事实、没有明显不满（如“还没用，等用了再评价”），人工标正向，v1 判中性 | 17 | 16 | #2643、#3371 |
| B. 夸产品但明确抱怨平台/价格，人工标负向，v1 判中性 | 5 | 5 | #7279、#5703、#8122 |
| C. 有小保留但整体接受，人工标正向，v1 判中性 | 4 | 4 | #3609、#3227 |
| D. 标签可能有歧义/噪声 | 3 | 1 | #4712、#5738、#2341 |
| 合计 | 29 | 26 | |

（归类是我人工判断的，属于定性分析；修好的数量来自 v2 的 `predictions.csv`。）

另外：v1 有 6 条评论一次给了 3 个标签（违反“最多 2 个”），被校验拦下，重问一次后全部修正，所以最终 JSON 失败率为 0。

**关键洞察：** 这个数据集的标签反映的是“评论者对这次购买的整体满意度”（很像星级），不是“文字有没有情绪”。电商里“还没用，等追评”的评论通常给的是好评；而“东西不错但京东太垃圾”通常给的是差评。

v2 的改动（代码见 `src/prompts.py` 里的注释）：

| 改动 | 针对的错误类型 |
|---|---|
| A. 把 sentiment 定义为“对这次购买的整体满意度（相当于会给几星）” | A、C |
| B. 明确写出：夸了产品但明确抱怨平台、物流、价格、客服 → 负向，原因用标签体现 | B |
| C. 明确写出：有小保留但整体接受 → 正向，并给了例子 | C |
| D. 中性只在完全没有评价倾向时使用，“应当很少出现” | A、C |
| E. 每个标签加一句话定义；强调最多 2 个、主要问题放第一个 | 3 个标签的情况、标签含义模糊（如平台账号问题归到“客服”） |
| F. 输出加一个 ≤15 字的 `reason` 字段 | 方便以后做 badcase 分析 |
| G. 加了一条“讽刺/反话按负向”的规则 | **预防性的**：v1 的错误里**没有出现讽刺案例**，这条规则不是由数据驱动的，也无法证明它起了作用 |

| 3371 | 生产日期很新，能用到19年12月份。还没有用，不知道效果1怎么样。 | 正向 | 中性 | 正向 ✅ | A 类：对已看到的东西（日期）是肯定的 |
| 7279 | 东西不错 京东太垃圾 | 负向 | 中性 | 负向 ✅ | B 类：产品好，平台差 → 整体不满。v2 标签从“其他”变为“客服” |
| 5703 | 商品还行但京东把我帐号弄成什么优惠券都不让领，这个1星是给京东的， | 负向 | 中性 | 负向 ✅ | B 类：评论者自己说了“1星”，最能说明标签=星级 |
| 8122 | 还可以，和图片相符！！就是价格贵了！！！！ | 负向 | 中性 | 负向 ✅ | B 类：价格抱怨 |

| 881 | 618之前买的，说是保价，享受便宜价，结果618还是降价了。不过总的来说超值吧。……不过到货的时候有点泄漏啊。 | 正向 | 正向 | 负向 ❌ | **v2 引入的新错误**：改动 B“有抱怨就判负”用力过猛，忽略了“总的来说超值吧”这个总结句 |

v2 在评测集上修好了 v1 的 26 个错误，同时新弄错了 3 个（#881、#3707、#1335），这 3 条都是**很长的评论**：对这次购买满意，但顺带抱怨了别的事（另一个商家的物流、别的平台的假货、几年前的快递事故）。#3707 就是典型的“产品很好，抱怨的是物流”，只不过抱怨的是**另一单**的物流。

## 5. 下一步（v3 的方向，尚未实现）

1. **只看这一单**：在 prompt 里区分“对这次购买的抱怨”和“对其他商品/其他平台/过去经历的抱怨”，后者不影响情感。
2. **总结句优先**：长评论里出现“总的来说/总之/整体”时，以总结句为准。
3. **新建 dev 集做 badcase 挖掘**：今后在单独的 dev 集上看 badcase、改 prompt，评测集只用来出最终数字，避免本次出现的“对评测集过拟合”。
4. **标签稳定性**：给出“什么时候加第二个标签”的明确规则（例如：只有第二个方面被明确评价时才加），然后用稳定性指标验证。
5. **标签质量**：完成 50 条人工标注，运行 `scripts/tag_agreement.py`，用真实一致率决定标签体系要不要调整。

## 6. 复现

```powershell
.venv\Scripts\python scripts\evaluate.py --version v1 --stability
.venv\Scripts\python scripts\evaluate.py --version v2 --stability
.venv\Scripts\python scripts\evaluate.py --version v1 --set holdout
.venv\Scripts\python scripts\evaluate.py --version v2 --set holdout
```
注意：`--stability` 会绕过缓存重新调用 API，每次结果可能略有不同。
